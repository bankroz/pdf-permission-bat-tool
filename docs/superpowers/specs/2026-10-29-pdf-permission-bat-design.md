# Windows 10 便携式 PDF 权限处理工具（BAT 版）设计

## 1. 目标

交付一个可直接复制、解压和运行的 Windows 10 x64 目录。用户双击 BAT 后可批量选择 PDF，或将一个及多个 PDF 拖到 BAT 上。工具调用随目录分发的 qpdf，为每个输入文件生成一个不带普通 PDF 加密权限限制的副本。

工具只面向用户有权修改的文档。它不猜测、不破解未知的打开密码，不上传文件，也不调用在线服务。

## 2. 范围

### 首版包含

- Windows 10 x64。
- BAT 双击入口。
- Windows 文件选择框，可一次选择多个 PDF。
- 将一个或多个 PDF 拖到 BAT 上处理。
- 随目录提供 qpdf 及其运行依赖和许可证。
- 批量处理、逐项状态、错误隔离、结果汇总。
- 原文件旁生成新副本，自动避免重名覆盖。
- 临时文件写入、结果检查和清理。
- 明确的密码、签名、损坏文件及写入权限提示。

### 首版不包含

- 图形化主界面、窗口内文件列表和进度条。
- 未知密码破解、猜测、字典或暴力尝试。
- 在线上传、账号、自动更新和遥测。
- 主动使用 `--remove-restrictions` 解除数字签名的认证限制。
- 保证修复所有“福昕打字机不可用”问题。

## 3. 事实与边界

- 很多“可以直接打开但禁止编辑或注释”的 PDF 使用空的用户密码，只设置权限限制。qpdf 可以打开这类文件并通过 `--decrypt` 生成不加密的副本。
- 真正要求输入打开密码的 PDF，首版在不知道密码时不能处理。
- 重新生成 PDF 可能使数字签名失效。首版不做签名检测，而是在开始处理前统一显示醒目警告。
- qpdf 返回码 `0` 表示没有错误或警告，`2` 表示错误，`3` 表示只有警告。返回码 `3` 的输出保留，但必须标记为“成功但有警告”。

参考：

- qpdf 加密设计：https://qpdf.readthedocs.io/en/stable/design.html
- qpdf 命令和退出状态：https://qpdf.readthedocs.io/en/latest/cli.html
- qpdf Windows 分发说明：https://github.com/qpdf/qpdf/blob/main/README-what-to-download.md

## 4. 技术方案

### 4.1 组件

1. `PDF权限处理工具.bat`
   - 用户可见入口。
   - 设置适合中文显示的控制台代码页。
   - 使用当前 BAT 所在目录定位 PowerShell 脚本，不依赖当前工作目录。
   - 将拖入的参数原样交给 PowerShell。

2. `tools/处理PDF.ps1`
   - 使用 Windows 10 自带的 Windows PowerShell 5.1 和 .NET Framework。
   - 双击启动且没有输入参数时，通过 `System.Windows.Forms.OpenFileDialog` 多选 PDF。
   - 校验输入、生成输出名、调用 qpdf、检查结果、清理临时文件并汇总状态。
   - 调用外部程序时使用参数数组，不拼接可执行的 shell 命令。

3. `qpdf/`
   - 使用 qpdf 12.4.2 官方 `msvc64` ZIP 分发包。
   - 保留 ZIP 中 qpdf 运行所需的目录结构和依赖。
   - 工具始终使用自身目录中的 qpdf，不读取系统 `PATH` 中的同名程序。

4. `licenses/`
   - 保存 qpdf 分发包包含的许可证和版权材料。

5. `使用说明.txt`
   - 描述双击多选和拖放两种用法、输出规则、安全边界、常见错误及版本信息。

## 5. 用户流程

### 5.1 选择文件

- 双击 BAT：打开“选择 PDF 文件”对话框，启用多选。
- 拖放：Windows 将一个或多个路径作为参数传给 BAT，脚本直接处理这些路径。
- 用户取消文件选择：正常退出，不显示错误。

### 5.2 开始前提示

处理前显示一次确认提示：

> 本工具仅处理你有权修改的文件。原文件不会被覆盖。处理后的副本可能使数字签名失效。是否继续？

用户拒绝则不处理任何文件。

### 5.3 单文件处理

对每个输入文件执行以下步骤：

1. 验证路径存在、类型为文件、扩展名为 `.pdf`。
2. 在原文件目录计算输出名：
   - 首选 `原文件名_可注释.pdf`；
   - 若已存在，依次尝试 `_可注释_2.pdf`、`_可注释_3.pdf`；
   - 绝不覆盖已有文件。
3. 在原文件目录创建带随机标识的临时输出路径，以保证最终移动发生在同一磁盘卷。
4. 通过参数数组调用随目录附带的 qpdf：

   ```text
   qpdf --decrypt 输入文件 临时输出文件
   ```

5. 读取 qpdf 退出码和错误输出，但不保存永久日志。
6. 只有退出码为 `0` 或 `3`，且临时输出存在并大于 0 字节时，才将其移动为最终输出名。
7. 返回码 `0` 标记为成功；返回码 `3` 标记为成功但有警告；其他情况标记为失败。
8. 在 `finally` 清理仍存在的临时文件。

每个文件有独立的异常边界。单个文件失败后继续处理下一文件。

### 5.4 完成提示

控制台逐项显示序号、输入文件名、结果和输出位置。完成后显示成功、警告成功、失败、跳过的数量，并等待用户按键，避免窗口立即关闭。

如果成功输出只涉及一个目录，询问用户是否打开该目录；涉及多个目录时只列出路径，不自动打开多个资源管理器窗口。

## 6. 错误映射

用户只看到可行动的中文提示，qpdf 的原始错误用于辅助归类，但不直接倾倒堆栈。

| 情况 | 用户提示 | 处理 |
|---|---|---|
| qpdf 不存在或不能启动 | 工具文件不完整，请重新解压完整目录 | 整批停止 |
| 输入不存在 | 文件不存在或已被移动 | 跳过该文件 |
| 非 PDF 扩展名 | 不是 PDF 文件 | 跳过该文件 |
| 需要打开密码 | 文件需要已知的打开密码，首版不支持无密码处理 | 失败并继续 |
| PDF 损坏或格式无效 | 文件损坏、格式无效或 qpdf 无法解析 | 失败并继续 |
| 原目录不可写 | 原文件目录没有写入权限，请复制到可写目录后重试 | 失败并继续 |
| qpdf 返回警告且输出有效 | 已生成副本，但 qpdf 报告文件结构警告 | 保留并标黄/标注警告 |
| 输出为空或缺失 | qpdf 未生成有效输出 | 失败并清理临时文件 |

错误识别优先使用 qpdf 退出码；文本匹配只用于给出更具体的中文建议，不作为成功判定依据。

## 7. 路径与进程安全

- 所有工具路径都相对于脚本自身目录解析。
- PowerShell 使用数组传递 qpdf 参数，不通过 `cmd /c` 拼接 qpdf 命令。
- 文件名可包含中文、空格、`&`、括号和感叹号。
- 不修改、不删除输入文件，不使用 qpdf 的 `--replace-input`。
- 不记录密码、PDF 正文或持久化文件清单。
- 不联网，不调用在线 API。
- PowerShell 的执行策略绕过仅限当前子进程，不修改系统或用户策略。

## 8. 测试设计

自动化测试重点覆盖 PowerShell 中可独立验证的路径和命名逻辑；集成测试使用临时目录和测试 PDF，不触碰用户原件。

测试集包括：

1. 单个普通 PDF。
2. 多个 PDF 批量处理。
3. 空用户密码、带编辑或注释限制的 PDF。
4. 真正需要打开密码的 PDF。
5. 损坏 PDF 和伪装成 `.pdf` 的文本文件。
6. 中文、空格、`&`、括号和感叹号路径。
7. 已存在 `_可注释.pdf` 和 `_可注释_2.pdf` 时生成 `_可注释_3.pdf`。
8. qpdf 缺失或不可执行。
9. 输出目录不可写。
10. 混合批次中一个文件失败，其余文件继续。
11. 处理前后原文件哈希、大小和修改时间不变。
12. 临时文件在成功和失败后都被清理。

## 9. 验收标准

- 在未安装 Python、未单独安装 qpdf 的 Windows 10 x64 电脑上，可从完整交付目录启动。
- 双击可多选 PDF，拖放可批量处理 PDF。
- 中文、空格和常见 shell 特殊字符路径可正常处理。
- 对能直接打开但受普通权限限制的测试 PDF，可生成不覆盖原件的新副本。
- 同名输出自动追加序号。
- 需要打开密码时不声称或尝试破解。
- 开始前明确提示数字签名风险。
- 混合批次中单个失败不影响其他文件。
- 所有处理均在本机完成。

## 10. 后续 UI 阶段接口

PowerShell 处理逻辑应把“单文件输入、结果状态、输出路径、用户提示”保持为清晰函数边界。后续 Tkinter/PyInstaller UI 可以复用同一套命名、错误映射和验收用例，而不必重新定义业务规则。BAT 版是处理闭环和测试基线，不是长期并行维护的第二套产品逻辑。
